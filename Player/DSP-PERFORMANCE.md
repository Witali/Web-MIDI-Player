# C/WASM и SIMD: результат эксперимента

18 октября 2026 года. Ветка C-ядра: `feature/c-wasm-audio-core`;
первоначальный WAT-прототип: `experiment/wasm-voice-dsp`.
Проверены JS, скалярный C/WASM и C/WASM SIMD128. **Эксперимент успешен:**
ускорение подтверждено в Node.js и встроенном браузере; результат перенесён
в `main`. При отсутствии поддержки WASM остаётся JS-режим.

## Что перенесено

В C/WASM выполняются интерполяция Hermite, фильтр biquad, расчёт огибающих
громкости и модуляции, смешивание голосов, панорамы и посылов эффектов,
chorus, линии задержки и Dattorro reverb. SIMD128 смешивает пары сэмплов
и в пакетном режиме считает два независимых фильтра через `f64x2`.
История каждого фильтра развивается последовательно, порядок огибающих
и смешивания голосов сохраняется. Разбор MIDI/SF2, MIDI-команды, настройка параметров
инструментов, LFO, расширенные GS/XG insertion-эффекты и часть маршрутизации
остаются в SpessaSynth. Граница C/JS явно описана в [native/README.md](native/README.md).

Сэмплы копируются в расширяемый WASM-кэш по одному разу. На аудиоблок основного стереорежима
16 и более голосов передаются одним пакетом огибающей громкости и рендера
JS → WASM; редкие партии сохраняют вызов на голос. Модуляционная огибающая
при необходимости вычисляется отдельным C-вызовом.
Нет покадровых JS-вызовов или копирования
его PCM между разными экземплярами WASM. Пул голосов расширяется независимо
от микшера. Отсечения голосов ради ускорения нет.

не гарантируют воспроизведение любой партитуры в реальном времени: сценарий
1024 нот всё ещё может превышать доступный процессорный бюджет.

## Проверка качества

- Побитное сравнение PCM с исходным JS для всех 128 GM-программ, 47 ударных,
  перекрывающихся release-хвостов, панорамы и включённых/выключенных эффектов.
- Проверка фильтра и его состояния, посылов reverb/chorus/delay/insertion,
  неполных и нечётных блоков 1, 3, 127 и 128 сэмплов.
- Проверки SMPTE, sustain, CC123/CC120, перемотки, плотной полифонии и JS fallback.
- **39 987** нативных C-проверок, включая огибающие, импульсный отклик эффектов,
  границы циклов, завершение сэмплов и смешивание 4096 голосов.
- **40** тестов JavaScript/WASM и каталога прошли без ошибок (`npm run test:all`
  из корня MIDI запускает также нативные C-проверки).
- Сравнение результата нативного C-кода с обеими WASM-сборками через JS ABI;
  проверка хешей C-исходников и бинарников и отсутствия JS-импортов DSP/математики.

Сохранены Float64-вычисления и исходные точки округления в Float32. Relaxed
SIMD и сокращение точности не используются. Обработка идёт в Worker; UI
получает готовые стереоблоки через AudioWorklet.

## Воспроизведение замеров и сборка

```sh
node Player/tools/benchmark-polyphony.mjs --rounds 5 --seconds 1 --output results.json
cd Player
npm run test:core
npm run build:dsp -- --emsdk /path/to/emsdk
npm test
```

Для обычного воспроизведения сборка и `npm install` не нужны: оба маленьких
WASM-файла включены в библиотеку. Проверка в браузере:
[example/benchmark.html](example/benchmark.html).

Сборщик: Emscripten **6.0.12**, только инструмент разработки. Исходники находятся
в `native/`, хеши — в `dsp/build.json`. Оба WASM-варианта собираются из одних
C-файлов; для SIMD добавляется `-msimd128`. Выбор вручную:
`new MidiPlayer({ dsp: 'js' })`, `'wasm'` или `'wasm-simd'`.
По умолчанию `'auto'`: скалярный C/WASM → SIMD → JS.

Спецификация возможностей SIMD: [документация V8](https://v8.dev/features/simd).

## Алгоритмическая оптимизация: адаптивный кэш волн

Ветка `perf/adaptive-wave-cache`. Профиль плотного рендера показал основную
нагрузку в обработке голосов. Выбранное изменение устраняет повторное вычисление
одинаковой исходной волны, а не уменьшает число звучащих нот.

В начале каждого блока хост вызывает `dsp_begin_block()`. C-кэш проверяет
указатель источника, параметры цикла/конца сэмпла, число кадров и точные биты
позиции/шага. Совпавший Hermite-буфер используется повторно. **Каждая нота
сохраняет собственные огибающие, фильтр, панораму, посылы и окончание**;
порядок суммирования и точки округления остаются прежними. EOF и рост памяти
проверены отдельными тестами.

1024 ячейки занимают около 0,56 МиБ. Это размер кэша: при коллизии волна
пересчитывается, голос продолжает звучать. Начальная WASM-память — 1 МиБ,
дальнейшее расширение арены сохранено. Кэш включается при ≥50% совпадений,
продолжает работать при ≥25%, иначе пропускает 15 блоков и снова проверяет
пользу. Разные пороги предотвращают частые переключения на границе полезности.

### Методика сравнения алгоритмов

База — `7e9edb8`, скалярный C/WASM. Новый вариант сравнивается с ней в одном
Node-процессе, порядок чередуется. Сохранены медианы времени расчёта ровно
48 000 стереокадров, все отдельные замеры, CPU-время процесса и медиана
отношений времени до/после в парных запусках. Последняя уменьшает влияние
изменений фоновой нагрузки; CPU-время включает служебные потоки Node и
имеет ограниченную точность. Загрузка банка/инициализация/прогрев исключены.
С `--expose-gc` сборка мусора запускается перед созданием каждого плеера.

Для воспроизведения нужен каталог предыдущего `Player` и восстановленный
SoundFont в текущей копии. Предыдущий каталог можно извлечь из `7e9edb8`;
сам банк в нём не нужен — обе версии получают один уже загруженный банк.

```sh
node --expose-gc Player/tools/benchmark-compare.mjs --baseline /path/to/previous/Player --notes 1024 --rounds 7 --output mixed.json
node --expose-gc Player/tools/benchmark-compare.mjs --baseline /path/to/previous/Player --notes 64 --scenario unison --output unison.json
node --expose-gc Player/tools/benchmark-compare.mjs --baseline /path/to/previous/Player --notes 256 --scenario staggered --output staggered.json
```

`mixed` — исходные 15 каналов/разные инструменты; `unison` — одинаковая высота
при раздельных каналах и тембрах; `staggered` — начала нот разнесены на 1 мс,
прогрев 1,25 с позволяет запустить все 256 нот до замера. Разные моменты начала
обычно исключают повторное использование исходной волны.

| Сценарий | Ноты | Эффекты | До, мс | После, мс | Парное ускорение |
|---|---:|:---:|---:|---:|---:|
| mixed | 1024 | нет | 1144,6 | 923,1 | 1,21× |
| mixed | 1024 | да | 1238,8 | 1034,6 | 1,21× |
| unison | 64 | нет | 77,0 | 46,5 | 1,61× |
| unison | 64 | да | 81,4 | 57,4 | 1,43× |
| staggered | 256 | нет | 250,7 | 259,5 | 0,97× |
| staggered | 256 | да | 280,1 | 288,7 | 0,97× |

Для mixed — 7 запусков, для остальных — 5. До/после — отдельные медианы;
последний столбец — медиана парных отношений, поэтому она может отличаться
от частного соседних столбцов. Исходные данные и хеши обеих сборок:
[mixed](dsp/benchmark-algorithm-mixed.json),
[unison](dsp/benchmark-algorithm-unison.json),
[staggered](dsp/benchmark-algorithm-staggered.json).

Ускорение зависит от совпадений. Для уникальных волн ожидается около прежней
скорости с небольшими накладными расходами: здесь **около 3–4%** по парным
замерам. Для смешанной плотной партии подтверждено около **21%** дополнительного
ускорения относительно прежнего C/WASM, для унисонов **43–61%**. Обещания
ускорить каждый MIDI нет.

Итоговая проверка во встроенном браузере, **1024 ноты с эффектами**, три
запуска: **JS 1671,3 мс; C/WASM 919,7 мс; C/WASM SIMD128 962,3 мс** на
секунду PCM. Это **1,82×** и **1,74×** относительно JS; сравнение с прежним
C/WASM выполнено отдельно в таблице выше. Обычное воспроизведение через
Worker/AudioWorklet также проверено, ошибок в консоли нет.

### Отклонённые варианты и следующие шаги

- Объединение интерполяции, фильтра и смешивания в один C-цикл сохранило PCM,
  но дало **0,71–0,74×** скорости базы. Код, соответствующие WASM и исходные
  замеры сохранены в **`experiment/fused-voice-pipeline`** (`d0cd04b`), файл
  `Player/FUSED-EXPERIMENT.md`. В рабочий движок этот вариант не включён.
- Специализация целой фазы/шага и кэш коэффициентов ускоряли отдельные
  микротесты до 1,5×, но не подтвердили устойчивого выигрыша полной партитуры.
- Пакетный C-вызов для голосов и постоянная история фильтров реализованы.
  Число переходов уменьшено; устойчивого ускорения всего плеера пока не доказано.
  Результаты и накладные расходы приведены ниже.
- Обход активных голосов и независимые SIMD-фильтры завершены и измерены ниже.
  Очереди с индексом головы также завершены и измерены ниже.


## Обход активных голосов (20 октября 2026)

База — main8a0db3174761c1f0aa9171b1c52ca3513074c428. Сравниваются реальные
модули синтезатора/DSP двух версий с одним загруженным SoundFont. Перед измерением
запускаются1024 ноты Stereo Saw:2048 голосов. После начального прогрева4096 кадров
плотный сценарий сохраняет их, остальные выполняют All Sound Off и запускают
четыре ноты(8 голосов) либо оставляют тишину. Для редкой партии дополнительно
рендерятся128+1024 кадров. Отдельный сценарий меняет MW/pan/expression четырёх
каналов на каждом блоке. Эффекты включены или выключены явно.

Измеряется48 000 кадров. Две версии чередуются по128 кадров; порядок меняется
между блоками и раундами. Это уменьшает влияние дрейфа фоновой нагрузки. Абсолютные
времена характеризуют такой парный запуск и не являются прогнозом нагрузки
единственного плеера: две версии делят кэши CPU/JIT. Инициализация, прогрев и
явный GC исключены. На каждой паре проверяется SHA-256 полного PCM, без допуска.
CPU-время записано суммарно для пары из-за низкой точности системного таймера.

Основной скалярный WASM,5 пар на сценарий, AMD Ryzen 5 5600X, Node v22.22.3:

| sparse-after-burst | нет | 12.01 | 7.75 | 1.57× |
| controls-after-burst | нет | 12.12 | 7.99 | 1.51× |
| silence-after-burst | нет | 4.65 | 0.73 | 6.40× |
| dense | да | 1223.33 | 1199.79 | 1.01× |

На плотной партии изменение в этом замере около1%; подтверждённого ускорения
плотного DSP этот пункт не обещает. После аккорда редкая партия быстрее в1,28–1,57×,
с контроллерами — в1,22–1,51×. При отсутствии активных голосов выигрыш в1,49–6,40×;

Предыдущий каталог Player извлекается из указанного Git-коммита; его SF2 не
используется, обе версии получают текущий проверенный банк. Воспроизведение:


остались прежними. Тест с2048 музыкальными нотами помечает все неактивные
слоты счётчиками чтения: последующий рендер/контроллеры не читают ни одного.


## Пакетная отправка голосов в C (20 октября 2026)

База — main `f221c33fd141dc7b9ff96655d38ce07301ffeee1`. В главном стереорежиме
16 и более записей активного списка готовят расширяемый массив команд, который
выполняется одним C-вызовом перед эффектами. При меньшем списке сохраняется
непосредственный рендер. Ограничения числа нот нет. Фильтры хранят историю
в постоянной WASM-памяти: вместо 9 полей из JS и 4 обратно теперь передаются
5 коэффициентов и 4 наблюдаемых поля обратно. При переходе с непосредственного
режима история синхронизируется один раз. Огибающая громкости остаётся
в прежнем связанном состоянии, а модуляционная огибающая при необходимости
по-прежнему требует отдельного C-вызова для подготовки высоты/фильтра.

В плотном сценарии за 48 000 кадров обработано 768 000 голосовых блоков:
**375 пакетных вызовов вместо 768 000 рендер-вызовов**. Это уменьшение именно
переходов рендера, а не всех C-вызовов программы. Состояния отдельных голосов,
порядок Float32-смешивания, последнее EOF-аудио и XG-шины сохранены побитно.
Массивы растут геометрически, перемещение payload обновляет уже записанные
указатели. В snapshots входят постоянные состояния, временные команды исключены.

Методика парного запуска прежняя: настоящие модули двух версий, один банк,
чередование 128-кадровых блоков, эффектов и порядка раундов; инициализация и GC
не измеряются. Для устойчивого замера обе версии сначала прогреваются редкой
партией на 65 536 кадров, затем плотной на 4096 кадров. Это дополнение нужно,
поскольку плотный прогрев обучает прежний непосредственный рендер, а новая
редкая ветвь иначе остаётся холодной. Холодный переход сохранён отдельно.
Указаны медианы времени и медиана отношений по парам; отношение двух медиан
может отличаться от медианы отношений. Абсолютные времена относятся к парному
запуску и не являются оценкой нагрузки одиночного браузерного плеера.

## SIMD по независимым голосам (20 октября 2026)

В пакетном SIMD-модуле две соседние команды с независимыми включёнными
фильтрами исполняются через f64x2: одна полоса соответствует одному голосу.
Постоянные состояния/ABI остаются прежними, при входе в пару поля двух
фильтров транспонируются в регистры SoA. Обратная связь внутри каждого
фильтра идёт по сэмплам последовательно. После gain применяется прежнее
округление Float32, затем голоса смешиваются в исходном порядке A → B.
Неотфильтрованные, одиночные и зависимые состояния выполняются прежним ядром.
Проверяются пересечения filter/envelope/capture с чтением/записью другого голоса,
включая исходные волны, входные блоки, таблицы, дескрипторы команд и общую
scratch-память. Вход копируется до обновления собственной огибающей; этот
порядок сохраняется и при их пересечении в памяти.

Расширяемый пул и размер команды 136 байт не меняются. В плотном сценарии
2048 голосов дают 1024 подтверждённые SIMD-пары на аудиоблок. Во время замера
исполнено 375 рендер-пакетов/768 000 голосовых блоков. Для проверки добавлены
последовательный экспорт в том же бинарном модуле и счётчики фактических пар;
дополнительные запросы статистики выполняются вне измеряемых блоков.

Сравнения используют настоящие synth/DSP-модули и один загруженный FluidR3 GM,
1024 ноты Stereo Saw / 2048 голосов, 48 000 кадров, 128-кадровые блоки и 5 пар
на сценарий. Прогрев — 65 536 кадров редкой партии и 4096 кадров плотной;
порядок двух плееров чередуется. Инициализация, прогрев и GC исключены.
Побитный PCM проверяется на каждой паре. CPU — AMD Ryzen 5 5600X,
Node v22.22.3; исходные времена и хеши модулей сохранены ниже.

## Очереди событий без shift() (20 октября 2026)

База — main `88d2cee9fa1794bb0b50ef2f3d6603ad840f9fcc`. Новая FIFO хранит
обычные поля items/head/length и немедленно освобождает ссылки потреблённых
элементов. Голова продвигается без сдвига оставшихся записей. После 1024
потреблённых позиций, когда потреблена хотя бы половина массива, pending-суффикс
копируется к началу. Стоимость обычных push/take амортизированно O(1); ссылки хранятся только
для pending-записей, логическое хранилище занимает O(pending + 1024) слотов. Порог компактизации
не ограничивает число сообщений или голосов.

Очередь будущих processMessage/processMessages сохраняет хронологию и порядок
при равном времени. Монотонные записи только добавляются в хвост; полный sort
после каждого push убран. Нарушившая порядок пачка стабильно сортируется при первом
наблюдении, с предварительной компактизацией. Checkpoints сохраняют обычные
поля, pending-записи и байты. Повторные Note On/Off в BasicMIDI.getNoteTimes
и каталожном ридере используют ту же FIFO и обходят при завершении только
непотреблённые записи. В standalone-каталог helper встраивается целиком.
C-ядро, ABI и WASM не менялись.

Секвенсор обычного SMF уже использовал индекс timeline и прямые вызовы synth.
Поэтому удаление shift относится к будущим timestamp-сообщениям и очередям
сопоставления нот. Два пути измеряются раздельно. Сдвиги в разовом слиянии
банков и сгенерированных bootstrap-callbacks компилятора сохраняются: они
не обрабатывают MIDI-поток при воспроизведении.

Инструмент загружает настоящие модули двух версий и один FluidR3 GM.
Сохраняются реальные SMF format 0 / PPQ 1000-файлы с 1000/4000/16000 контроллерами.
Две ноты Stereo Saw удерживаются от 0 до 0,75 с; пачка CC1/10/11/74 находится
на 0,5 с. Повторяющиеся значения/время сохраняются, каждый raw message проверяется
по идентичности и позиции, включая Program Change и Note On/Off. В raw API
весь файл заранее передаётся через options.time; отдельно замеряются enqueue,
первый блок наблюдения и блок исполнения due-пачки. Остальной рендер префикса
и хвоста выполняется для полного сравнения 60000 PCM-кадров (1,25 с), но не
входит в сумму queue-фаз. Эффекты выключены, DSP — scalar WASM. Обычный
SMF проигрывается штатным createSoundFontPreview, где измеряется весь рендер.
