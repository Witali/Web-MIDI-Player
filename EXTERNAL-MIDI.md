# Подключение внешних MIDI-устройств

Web-MIDI-Player может принимать MIDI-команды от инструментов, играть ими
через свой банк звуков и отправлять команды внешним синтезаторам.
Эта возможность сохранена как отдельная интеграция. В обычном каталоге,
публичной библиотеке и стандартном примере панель устройств отключена;
для её подключения нужна отдельная страница по инструкции ниже.

## Какие устройства можно подключить

Устройство должно предоставлять MIDI-порт операционной системе, а браузер —
показывать этот порт через Web MIDI. Наличие USB-разъёма само по себе
не означает поддержку MIDI: смотрите режим USB MIDI и драйвер устройства.

| Устройство | Как подключить | Что можно делать в нашей программе |
| --- | --- | --- |
| MIDI-клавиатура, клавишный USB-контроллер | USB или MIDI OUT клавиатуры → MIDI IN компьютерного интерфейса | Играть звуками нашего банка; принимать ноты, силу нажатия, педали, pitch bend и другие MIDI-команды. |
| Цифровое пианино | USB MIDI либо MIDI-интерфейс | Использовать клавиатуру как MIDI-вход. Если пианино принимает MIDI, отправлять ему команды для воспроизведения его собственными тембрами. |
| Аппаратный синтезатор с клавишами | USB MIDI или MIDI IN/OUT через интерфейс | Получать команды от клавиатуры и регуляторов; отправлять команды звуковому генератору синтезатора. Возможность каждого направления зависит от модели. |
| Звуковой модуль, рэковый или настольный синтезатор | USB MIDI или MIDI IN через интерфейс | Использовать как MIDI-выход: звук создаёт сам модуль. Клавиши на нём не обязательны. |
| Электронная ударная установка, MIDI-пэды | USB MIDI либо MIDI OUT через интерфейс | Получать удары как ноты с velocity, играть ударными нашего банка или пересылать их другому инструменту. Номера нот и канал должны соответствовать выбранному набору ударных. |
| MIDI-педаль, ножной контроллер, фейдеры и регуляторы | USB MIDI или MIDI-интерфейс | Принимать ноты, Control Change и Program Change. Для управления кнопками каталога потребуется отдельно назначить действия в коде сайта. |
| Духовой MIDI-контроллер, гитарный MIDI-контроллер | MIDI-выход контроллера через USB или интерфейс | Получать ноты и выразительные контроллеры; звучание определяется поддержкой команд и модуляторами выбранного банка. |
| USB–MIDI-интерфейс, MIDI-порты аудиоинтерфейса | USB к компьютеру, MIDI-кабели к инструментам | Подключать инструменты с MIDI IN/OUT. Сам MIDI-интерфейс переносит команды; звуковой генератор нужен в программе или в инструменте. |
| Программный синтезатор, DAW | Виртуальный MIDI-порт, установленный и настроенный в ОС | Передавать команды в программу или получать их из неё, если виртуальный порт доступен браузеру. Сам VST-плагин напрямую в браузер не загружается. |
| Bluetooth MIDI-устройство | Системное подключение BLE MIDI, если его поддерживают ОС и драйвер | Работать с ним как с MIDI-портом, когда он появился в системе и доступен Web MIDI. Отдельного сопряжения Bluetooth внутри нашей программы нет. |

Управление тембрами, банками и специфическими функциями внешнего инструмента
зависит от его MIDI Implementation Chart. Для игры с пэдов назначьте им
нужные MIDI-ноты; стандартные GM-ударные обычно передаются по каналу 10.
Сейчас один объект `WebMidiPorts` выбирает один вход и один выход.
Для нескольких устройств можно создать отдельные экземпляры в своей
интеграции или настроить объединение/маршрутизацию портов средствами ОС.

## Где создаётся звук

| Маршрут | Кто создаёт звук | Что включить на панели |
| --- | --- | --- |
| Клавиатура → браузер → банк Web-MIDI-Player | Наш синтезатор, звук через аудиовыход компьютера | Выбрать MIDI-вход и нажать «Включить звук входа». |
| Сайт → MIDI-выход → внешний синтезатор | Внешний инструмент, звук через его аудиовыход | Выбрать MIDI-выход; проверить кнопкой «Пробная нота на выход». |
| Клавиатура → браузер → внешний синтезатор | Внешний инструмент | Выбрать вход и выход, включить «MIDI Thru: вход → выход». |
| Сайт → виртуальный порт → программный синтезатор | Программный синтезатор | Настроить порт в ОС и в синтезаторе, затем выбрать его как MIDI-выход. |

MIDI передаёт команды: какую ноту включить, с какой силой, когда отпустить,
какой тембр выбрать. Аудиосигнал внешнего синтезатора подключают к колонкам,
наушникам или аудиоинтерфейсу отдельно. Он не возвращается в страницу по MIDI.
При одновременном включении звука входа и MIDI Thru могут звучать оба
синтезатора: наш и внешний.

## Подготовка инструмента и браузера

1. Подключите инструмент к компьютеру. Для USB выберите режим MIDI,
   если он переключается в настройках устройства, и установите драйвер,
   если этого требует изготовитель.
2. Для обычных MIDI-разъёмов соедините MIDI OUT инструмента с MIDI IN
   интерфейса, чтобы принимать команды. Для передачи команд соедините
   MIDI OUT интерфейса с MIDI IN инструмента. Ориентируйтесь на назначение
   разъёмов в инструкции к интерфейсу.
3. Проверьте, что ОС видит MIDI-порт. Для программного синтезатора сначала
   создайте виртуальный порт и выберите его в настройках синтезатора/DAW.
4. Откройте страницу в браузере с поддержкой Web MIDI через HTTPS или
   локальный адрес, например `http://127.0.0.1:8767/`.
   Доступ проверяется выражением `typeof navigator.requestMIDIAccess === 'function'`.
5. Нажмите «Разрешить MIDI» и разрешите доступ в браузере. Затем явно
   выберите нужные порты: само разрешение ещё не подключает инструмент.

Требования к защищённому контексту и разрешению описаны в
[MDN: Web MIDI API](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API).
Проверяйте там же актуальную совместимость браузеров. Хостинг должен разрешать
функцию `midi` в своей Permissions Policy; запрет `midi=()` блокирует доступ.

## Как добавить отдельную страницу с панелью устройств

Самый простой способ встраивания — скопировать полную исходную папку
`Player/` на свой сайт. Она уже содержит необходимые модули, банк и плеер;
проверьте восстановление Git LFS и выполните `npm run setup`.
На сайте назовите эту папку `player` в нижнем регистре — так она указана
в импортах примера ниже.

Если вы берёте готовый плеер из `dist/public-library/player/` или
`downloads/player/`, дополнительно скопируйте в его папку эти шесть файлов
из исходной `Player/` той же версии:

- `web-midi.js` — доступ к портам, ввод, вывод и MIDI Thru;
- `live-midi.js` — управление отдельным синтезатором для живого входа;
- `live-synth.js` — обработка команд и подготовка нужных сэмплов;
- `live-worker.js` — синтез в Worker;
- `live-worklet.js` — передача звука в Web Audio;
- `devices-view.js` — готовая панель выбора устройств и проверки команд.

`index.js` эти модули не экспортирует: используйте прямые импорты.
Повторная сборка каталога снова исключает их из экспортируемого плеера,
поэтому храните страницу интеграции отдельно от генерируемого каталога.

Например, для проверки на этом компьютере выполните из корня репозитория
следующие команды PowerShell. Получится отдельный сайт в игнорируемой папке
`.cache/midi-devices-site/`:

```powershell
npm run setup
npm run catalog:public
$deviceSite = '.cache/midi-devices-site'
New-Item -ItemType Directory -Force -Path "$deviceSite/player", "$deviceSite/midi" | Out-Null
Copy-Item -Path 'dist/public-library/player/*' -Destination "$deviceSite/player" -Recurse -Force
$optionalModules = @('web-midi.js', 'live-midi.js', 'live-synth.js', 'live-worker.js', 'live-worklet.js', 'devices-view.js')
foreach ($module in $optionalModules) {
    Copy-Item -LiteralPath "Player/$module" -Destination "$deviceSite/player/$module" -Force
}
```

Сохраните следующий HTML как `.cache/midi-devices-site/index.html`:

```html
<!doctype html>
<html lang="ru">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Web-MIDI-Player — внешние инструменты</title>
<h1>Внешние MIDI-инструменты</h1>
<div id="devices"></div>
<script type="module">
  import { LiveMidiPlayer } from './player/live-midi.js';
  import { renderMidiDevices } from './player/devices-view.js';

  const live = new LiveMidiPlayer({ volume: 0.55, effects: true, dsp: 'auto' });
  const removeView = renderMidiDevices(document.querySelector('#devices'), live, {
    onError: error => console.error(error),
  });

  // При удалении панели из приложения вызовите removeView(),
  // затем await live.dispose(), чтобы освободить звук и MIDI-порты.
</script>
</html>
```

Запустите уже имеющийся в проекте сервер на отдельном порту:

```powershell
node catalog-server.mjs --output .cache/midi-devices-site --port 8767 --open
```

Откроется `http://127.0.0.1:8767/`. Серверу нужна папка `midi/`,
созданная командами выше; для проверки клавиатуры MIDI-файл в ней не нужен.
Для размещения на своём сайте перенесите `index.html` и папку `player/`
на HTTPS-хостинг с поддержкой JavaScript-модулей, WASM, Worker и AudioWorklet.
Сохраняйте лицензии и файлы банка вместе с плеером.

## Как пользоваться панелью

1. Для обычной игры оставьте «Разрешить SysEx» выключенным. Для работы
   с программным синтезатором включите «Показывать программные MIDI-устройства»
   перед запросом доступа; доступность портов зависит от ОС и браузера.
2. Нажмите «Разрешить MIDI», затем выберите «MIDI-вход» для клавиатуры
   и/или «MIDI-выход» для синтезатора.
3. Чтобы играть нашим банком, нажмите «Включить звук входа» и дождитесь
   загрузки. Нажатия клавиш после этого поступают в отдельный синтезатор.
   Он загружает сэмплы используемых инструментов по необходимости.
4. Чтобы проверить внешний синтезатор, нажмите «Пробная нота на выход».
   Отправляется нота 60 по каналу 1 с отпусканием через 300 мс.
5. Для пересылки команд клавиатуры внешнему синтезатору включите MIDI Thru.
   Проверьте, что обратная маршрутизация в синтезаторе/DAW не замыкает
   MIDI-петлю.
6. «Выключить все ноты» останавливает ноты локального синтезатора и
   отправляет команды остановки на выбранный MIDI-выход.
   «Выключить звук входа» останавливает только локальный звуковой тракт;
   MIDI Thru управляется своей галочкой.

После отключения кабеля устройство нужно выбрать заново. Кнопка
«Обновить разрешения MIDI» также сбрасывает выбор портов при успешном запросе.
Параметр SysEx разрешает специальные команды инструмента и нужен только
для соответствующих функций. Его поведение и запрос программных
синтезаторов определены в [Web MIDI, MIDIOptions](https://www.w3.org/TR/webmidi/#midioptions-dictionary).

## Как отправлять свои команды в коде сайта

Для собственного интерфейса можно использовать только `WebMidiPorts`,
без локального синтезатора и звукового банка:

```js
import { WebMidiPorts } from './player/web-midi.js';

const ports = new WebMidiPorts();
// В обработчике кнопки «Подключить»:
const available = await ports.request({ sysex: false, software: false });
// Покажите available.inputs / available.outputs в своих списках.
// inputId и outputId — идентификаторы портов, выбранных пользователем.
await ports.selectInput(inputId);
await ports.selectOutput(outputId);

ports.addEventListener('midimessage', event => {
  const { data, timestamp, port } = event.detail;
  console.log(port.name, timestamp, Array.from(data));
});

ports.send([0xc0, 0]);       // Program Change: первый тембр, канал 1
ports.send([0x90, 60, 100]); // Note On: нота 60, velocity 100, канал 1
ports.send([0x80, 60, 0], performance.now() + 300);
// При необходимости: ports.thru = true;
// При остановке: ports.panic();
// При удалении интеграции: await ports.dispose();
```

Если нужен только выход, пропустите `selectInput`; для одного входа
пропустите `selectOutput` и вызовы `send`. `selectInput(null)` и
`selectOutput(null)` отключают выбранный порт.
В байтах MIDI каналы кодируются числами 0–15, в интерфейсах инструментов —
обычно 1–16; поэтому `0x90` означает Note On на канале 1.
Момент отправки — абсолютное время в миллисекундах по шкале
`performance.now()`, а не длительность ожидания. На выход подаются полные
MIDI-сообщения; данные файла SMF и running status передавать напрямую нельзя.
Формат и порядок отправки заданы в [Web MIDI, MIDIOutput](https://www.w3.org/TR/webmidi/#midioutput).

## Возможности и границы текущей реализации

Локальный синтезатор и файловый плеер работают независимо: клавиатура
не меняет позицию, цикл или контроллеры загруженного MIDI-файла.
Приём нот, выбор портов, MIDI Thru, тестовая нота и отправка собственных
команд уже реализованы. Совместимость отдельных MIDI-команд с нашим банком
описана в [Player/README.md](Player/README.md#sound-and-instrument-coverage).

Автоматическое воспроизведение целого MIDI-файла через внешний MIDI-выход
пока не реализовано. Отдельной доработки потребуют маршрутизация событий
файла с учётом темпа/паузы/перемотки и назначение физических регуляторов
кнопкам интерфейса. Включение панели само по себе этих функций не добавляет.
Для программных синтезаторов нужен доступный системный MIDI-порт;
поддержки загрузки VST/AU-плагинов в этой библиотеке нет.

## Если устройство видно, но ничего не происходит

| Симптом | Что проверить |
| --- | --- |
| Нет кнопки устройств в обычном каталоге | Это отдельная опциональная интеграция; используйте страницу с панелью из этой инструкции. |
| Web MIDI недоступен | Поддержку браузера, адрес HTTPS/localhost, разрешение сайта и Permissions Policy. |
| Список портов пуст | Кабель с передачей данных, питание, USB MIDI-режим, драйвер и наличие MIDI-порта в ОС. Для программных устройств — виртуальный порт и соответствующую галочку. |
| Входящие сообщения есть, звука нашего банка нет | Выбран ли вход, включён ли «Звук входа», завершена ли загрузка банка, громкость и аудиовыход браузера. |
| Пробная нота отправляется, внешний инструмент молчит | Выбранный MIDI-выход, режим приёма инструмента, канал 1, громкость и его отдельное аудиоподключение. |
| Ударные звучат как фортепиано или не теми барабанами | MIDI-канал и соответствие нот набору ударных; для GM обычно нужен канал 10. |
| Ноты повторяются или зависают | MIDI-петлю, одновременные маршруты Thru в DAW/инструменте; используйте «Выключить все ноты». |
| После переподключения нет ввода | Снова выберите устройство; автоматически повторно оно не подключается. |

Физические модели и драйверы проверяются с реальным оборудованием.
Автотесты проекта проверяют работу портов на моделях устройств, очередь
MIDI-команд, синтез через Worker/WASM и управление звуковым трактом.
