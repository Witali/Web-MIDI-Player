# Web-MIDI-Player

Локальный каталог MIDI: поиск, избранное, фильтры, версии мелодий и прослушивание.

## Запуск

Требуется Node.js 22 или новее; для распаковки банка звуков нужен `tar`.
После клонирования выполните `npm run setup`: команда проверит имеющийся банк
и при необходимости скачает его. Затем запустите `Открыть каталог.cmd` или `npm start`.
Адрес каталога: http://127.0.0.1:8765/. Окно сервера должно оставаться открытым.

Коллекция располагается в `downloads/midi/`, её метаданные — в
`downloads/manifest.json`. После обновления локального архива выполните
`npm run catalog`. Файл `downloads/index.html` поддерживает поиск при прямом
открытии; для звука нужен локальный HTTP-сервер.

## Публичный каталог для сайта

`npm run start:public` собирает и открывает отдельный каталог по адресу
http://127.0.0.1:8766/. Он содержит восемь редакций Public Domain из Mutopia:
«К Элизе», «Турецкий марш», The Entertainer, Maple Leaf Rag,
три гимнопедии Сати и Ave Maria Гуно.

Для подготовки статического сайта выполните `npm run setup`, затем
`npm run catalog:public`. Размещайте содержимое `dist/public-library/`
на HTTP/HTTPS-хостинге с поддержкой WASM и отдельных Ogg/PCM-сэмплов. Отдельный сервер API и CORS-прокси не требуются.

Сборка берёт только файлы из `public-library/manifest.json`, проверяет
статус, источники и SHA-256 MIDI и исходных нот. Она включает плеер,
банк звуков, лицензии и ноты; личная коллекция `downloads/` в неё не входит.
Карточки и CSV содержат сведения о правах и авторах набора.
Добавление произведений описано в `public-library/README.md`.

Каталог `dist/public-library/` генерируется заново при каждой сборке;
не храните в нём собственные исходники. Для локальной личной библиотеки
по-прежнему используются `npm run catalog` и `npm start`.

## Установка приложения и локальные MIDI

Страница работает как Progressive Web App. Откройте её по HTTPS
(например, на GitHub Pages) или через локальный сервер.
В настольных Chrome/Edge установите Web-MIDI-Player кнопкой
**«Установить приложение»**, когда её предложит браузер, либо через меню
установки в адресной строке. Приложение открывается в отдельном окне.

Локальный файл можно открыть кнопкой **«Открыть MIDI…»**, перетащить в окно
или выбрать через `Ctrl+O` (`⌘O` на macOS). Поддерживаются `.mid`,
`.midi`, `.rmi` и `.kar`. После открытия нажмите ▶ в плеере.
Файл читается в памяти на компьютере; его содержимое не отправляется на
сервер и не добавляется в нашу подборку `public-library/`.

После установки в поддерживающем File Handling API браузере приложение
можно выбрать в системном меню **«Открыть с помощью»** для этих расширений.
Разрешите браузеру открыть выбранный файл; при желании назначьте
Web-MIDI-Player приложением по умолчанию средствами ОС.
Эта системная интеграция доступна в настольных Chromium-браузерах;
в остальных браузерах остаётся обычный выбор файла.
[Описание File Handling API](https://developer.chrome.com/docs/capabilities/web-apis/file-handling).

Для полного воспроизведения без интернета один раз нажмите
**«Скачать для офлайн»** и дождитесь **«Офлайн готов»**. Сохраняются
интерфейс, плеер, отдельные сэмплы банка и наша подборка. После этого
можно закрыть приложение, отключить сеть, снова открыть его и выбрать
новый MIDI с компьютера. Без этой команды сэмплы по-прежнему загружаются
по необходимости; уже полученные ресурсы сохраняются для повторного использования.
Сами выбранные локальные MIDI в офлайн-кэш не записываются.
Обновление установленной версии применяется после закрытия всех окон
приложения и повторного запуска; при смене версии банк для полного офлайн
может понадобиться сохранить заново.

## GitHub Pages

Репозиторий подготовлен для публикации по адресу
[Witali.github.io/Web-MIDI-Player](https://witali.github.io/Web-MIDI-Player/).
Для первого запуска:

1. Откройте репозиторий на GitHub: **Settings → Pages → Build and deployment**.
2. В поле **Source** выберите **GitHub Actions**.
3. Откройте **Actions → Publish library to GitHub Pages → Run workflow**
   и выберите ветку `main`.
4. Дождитесь успешного задания `deploy`; оно покажет ссылку на сайт.

Публикация запускается вручную. Обычный push в `main` сам по себе сайт
не обновляет. Workflow находится в [.github/workflows/pages.yml](.github/workflows/pages.yml).
Он восстанавливает через Git LFS только браузерный банк, устанавливает
зависимости, проверяет каталог и диалоги, собирает сайт и проверяет
воспроизведение MIDI по пути `/Web-MIDI-Player/` в Chromium.
Для этой сборки не требуется скачивать исходные SF2 или устанавливать C-компилятор.

В Pages передаётся только `dist/public-library/`: наша сохранённая подборка,
исходные ноты, лицензии, плеер и отдельные сэмплы. Персональные `downloads/`
и исходники всего репозитория в артефакт сайта не попадают.
Файлы сборки не нужно коммитить или переносить в отдельную ветку.

Локальная проверка перед публикацией после установки браузера Playwright:
`npm run test:pages`. Она собирает тот же сайт и проверяет загрузку модулей,
MIDI, WASM и сэмплов с префиксом имени репозитория.
Для включения автопубликации можно дополнить `on` в workflow:

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

Настройка источника описана в
[документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Дополнительная возможность: внешние MIDI-устройства

В проекте сохранены модули MIDI-ввода, вывода, MIDI Thru и игры с внешней
клавиатуры через банк плеера. Эта возможность отключена в обычном интерфейсе
и не входит в сборки каталогов: они предназначены для воспроизведения файлов.
Её можно подключить отдельно при встраивании библиотеки;
[список устройств, схемы и пошаговое подключение](EXTERNAL-MIDI.md).

## Git и локальные данные

Личная MIDI-коллекция, скачанный архив, зависимости, кэши и скраппер не хранятся
в Git. Проверенная публичная подборка `public-library/` включена в репозиторий.
При очистке репозитория и истории Git сохраняйте эту подборку целиком:
её MIDI, исходные ноты, `manifest.json` и сведения о правах нужны сайту.
Не включайте `public-library/` в фильтры удаления MIDI-файлов.
Исходники скраппера и прежняя инструкция `SCRAPER-LOCAL.md` остаются на этом
компьютере. Каталог не импортирует код скраппера и не запускает сетевое скачивание.
После клонирования добавьте собственную локальную коллекцию и её manifest.json.

`npm test` проверяет чтение MIDI, каталог и локальный HTTP-сервер.

Браузерные проверки интерфейса запускаются отдельно:

```sh
npm ci
npx playwright install chromium
npm run test:ui
```

Тест прокручивает длинное содержимое всех пяти окон на широком, узком
и низком экране: крестик должен оставаться на месте, быть видимым
и закрывать окно по нажатию. Используются настоящие HTML, CSS,
рендерер отчёта и обработчики каталога; личная коллекция и банк звуков
для этой проверки не нужны. При ошибке снимок экрана и трассировка
сохраняются в `.cache/playwright/`.
Можно использовать установленный Chrome, задав переменную окружения
`PLAYWRIGHT_CHANNEL=chrome` вместо установки Chromium.
`npm run test:all` включает также браузерные проверки (для нативных
тестов ядра нужен C-компилятор).

## Сэмпловый плеер

`Player/` — самостоятельная библиотека для любого статического сайта. API,
пример встраивания, лицензии и источники описаны в `Player/README.md`.
В каталоге она воспроизводит MIDI в стерео с банками FluidR3 GM + GS:
128 инструментов General MIDI, GM-ударные и панорама CC10.
Кнопка «Темп и повтор» настраивает скорость, транспонирование и цикл всей
композиции/A/B; tempo map исходного MIDI сохраняется.

Банки FluidR3 GM + GS (MIT) включены в репозиторий через Git LFS: исходный
GM SF2 (142 МиБ), GS-дополнение (3,1 МиБ) и 1 454 отдельные записи для
браузера (31,0 МиБ вместе). Плеер
по умолчанию скачивает только сэмплы, необходимые выбранному MIDI, до начала
воспроизведения; смены инструментов, банков, ударные и MIDI-порты учитываются.
Записи сжаты Ogg Vorbis, как в тестере Z80; короткие записи оставлены PCM16.
Публичная сборка содержит отдельные сэмплы и не включает исходные SF2.
GS-дополнение добавляет 33 пресета; таблицы адресов и явных замен GM2/XG
описаны в `Player/BANK-COVERAGE.md`.
Перед клонированием установите Git LFS и выполните `git lfs install`;
для уже скачанного репозитория выполните `git lfs pull`. Лицензия банка
сохранена в `Player/licenses/FluidR3-MIT.txt`.

Команда `npm run setup` (также доступна как `npm run player:assets`)
использует скрипт `Player/tools/fetch-assets.mjs` и проверенные ссылки на
[пакет FluidR3 GM 3.1 из Debian](https://deb.debian.org/debian/pool/main/f/fluid-soundfont/fluid-soundfont-gm_3.1-5.3_all.deb).
Архив GM занимает около 114 МиБ, извлечённый банк — около 142 МиБ.
Отдельно проверяется [GS-дополнение](https://deb.debian.org/debian/pool/main/f/fluid-soundfont/fluid-soundfont-gs_3.1-5.3_all.deb)
(архив 2,4 МиБ).
Скрипт проверяет SHA-256 архива и банка; повторный запуск не скачивает
уже проверенный банк. Также проверяются все файлы браузерных сэмплов.
Готовые файлы восстанавливаются через Git LFS; для их пересборки без Git LFS
нужен FFmpeg с libvorbis (`npm run player:samples`).
Затем восстановите свою коллекцию в `downloads/` и выполните `npm run catalog`.
Готовый каталог содержит автономную копию плеера в `downloads/player/`.
Пример: http://127.0.0.1:8765/player/example/index.html.

Исходный проект Z80 не изменялся. Его компактный движок также доступен
в библиотеке через `new MidiPlayer({ engine: 'z80' })`.
